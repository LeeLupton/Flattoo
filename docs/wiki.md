# The wiki: user education Ask Flattoo can pull from

`wiki/pages/*.md` are the artist's help pages — plain English, one topic
each, with a metadata block the copilot reads. `pkgs/flattoo-wiki` renders
them to static HTML (`Help & How-To` in the menu, `flattoo-wiki`), and
publishes `index.json` so **Ask Flattoo answers "how do I…" by opening the
right page**. Screenshots of the real desktop are generated in a VM and
committed.

## How a request reaches a page

```
"how do I scan a sketch"
   └─ flattoo-copilot: a question (how do I / what is / where is / show me / explain / is it…)
        └─ flattoo-wiki search --json  (one ranking implementation, shared)
             questions  exact phrase +3, fuzzy ≥0.7 → +2·ratio
             tags/title/menu names on word boundaries +1, fuzzy words +0.6
             summary words +0.15
        └─ best page ≥ 1.0 → action "learn" {page, candidates}
             → confirmation-free: opens file:///run/current-system/sw/share/flattoo/wiki/<id>.html
               (several close hits → a list to pick from)
```

Order matters: a printer complaint still goes to the printer actions, a
named app to open/install, a status question ("is it up to date") to the live
answer; the wiki answers the rest. Anything unmatched falls back to the wiki
before giving up, so "I don't know how to do that" only appears when neither
the actions nor the pages cover it. With an LLM provider enabled, the page
list (id, title, summary) is in the model's context and `learn` is one of the
actions it may choose; the page id is validated against the index like
everything else.

## Page format

```markdown
---
id: sketch-to-stencil              # file name, URL, copilot handle
title: From a pencil sketch to a stencil
summary: Scan or photograph the sketch, right-click it for Clean Lines, then Print as Stencil.
category: printing                 # desktop | drawing | printing | phone | system | safety
order: 6                           # position on the front page
tags: [sketch, scan, scanner, pencil, clean lines, trace]
questions:                         # the phrasings that must land here (tested)
  - how do I scan a sketch
  - turn my drawing into a stencil
actions: [open, print]             # copilot actions this page explains (must exist)
menu: [Document Scanner, Clean Lines (Sketch to Stencil), Print as Stencil]
shortcuts: ["Super+P"]
screenshots: [files-right-click, print-stencil]   # ids from wiki/screenshots
related: [print-stencil, calibrate]               # must exist
---
Markdown body. Tables, lists, links to other pages as `other-id.html`.
```

`index.json` carries all of this per page plus each screenshot's file,
thumbnail and caption, and `missing_screenshots` for the ones not yet
captured (the page shows a dashed placeholder until they are).

Writing rules: US English, plain words, say what to click. No terminal
commands on artist pages — Ask Flattoo is the terminal. Facts are checked
against the configuration (which folder Simple Scan saves to, which keys a
look binds), not assumed.

## Screenshots

`tests/screenshots.nix` is a NixOS VM test (`nix build .#screenshots`) that
boots the shop-laptop modules without the disk layout, auto-logs the artist
in and drives the real desktop: all six looks, the menu, Ask Flattoo and its
suggestion list, the Looks / Layouts / Lock dialogs, Print as Stencil, Fix
Stencil Printer, the Bluetooth and network printer wizards, Files with the
right-click menu, two layouts with Krita, Ristretto, Firefox and Thunar
running, the lock screen, and a second boot into the i3 session. Each
`machine.screenshot()` is paired with a caption; the run writes
`index.json` next to the PNGs.

`scripts/update-screenshots.sh` runs it and copies the result into
`wiki/screenshots/`. Commit. The wiki package renders from the committed
files, so the laptop never runs a VM and CI never needs KVM. Without
`/dev/kvm` the VM runs under TCG — slow but it works; the script passes the
`kvm` system feature so the test derivation is accepted and QEMU falls back
on its own.

Re-run it when a look, a dialog or the panel changes. The content test does
not fail on missing screenshots (pages render with placeholders); `flattoo-wiki
check` lists them.

## Tests (`checks.wiki-content`)

* every page has id, title, summary, category, tags, questions; ids unique;
  `related` and `actions` refer to things that exist (actions come from
  `flattoo-copilot --list-actions`);
* every question a page lists ranks that page first in `flattoo-wiki search`;
* the copilot, with the wiki in reach, maps a set of questions to `learn`
  with the right page, and still sends "the printer isn't working" to the
  printer fix, "install pinta" to install, "dark mode" to Looks.
